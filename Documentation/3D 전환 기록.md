# 3D 전환 — 2026-09-26

사용자가 요청한 3D 방향을 기준으로 이전 도트 월드를 교체했다. 원본 기획 문서와 캐릭터 이미지는 보존했다. 이전 상세 기획서의 2D 표현 지침보다 이 전환 지시가 우선한다.

## 현재 구조

- 탐험: XZ 바닥 좌표 위에서 움직이는 실제 메시 캐릭터와 입체 가구. 14개 구역을 모두 동일한 3D 렌더링 경로로 전환했다.
- 카메라: 원근 투영, 사선 추적, 1280×720 내부 렌더링, 4배 멀티샘플링. 도트 확대용 Point 필터와 픽셀 위치 정렬을 제거했다.
- 환경: 바닥 슬래브, 입체 벽과 창틀, 가구, 장비, 문, 배관, 실시간 조명과 그림자. 앞쪽 벽은 플레이어를 가리지 않는 낮은 단면 구조다.
- 인물: 다은의 갈색 묶은 머리·작업복, 제임스의 금발·안경·긴 겉옷, 다니엘의 붉은 머리·체격·어깨 패치를 반영했다. 경비·연구원·소장도 별도 입체 모델로 표시한다.
- 동작: 다리와 팔을 분리한 걷기·달리기, 방향 회전, 전문 행동, 누웠다가 일어나는 자세, 전투 행동과 반격 동작.
- 타이틀·전투·엔딩: 별도 3D 세트와 카메라로 표시한다. 대화·파티 초상화도 3D 모델을 실제 렌더링해 사용한다.
- 이동과 상호작용: 기존 저장 좌표를 XZ로 매핑한다. 구역 내 바닥 이동은 사각 충돌 영역으로 제한하며 물체에는 대응하는 3D Collider를 부착한다. 자유 점프·높낮이 물리 시뮬레이션은 추가하지 않았다.
- 진행: 제작, 동료 교체, 단서, A/B/C 퍼즐, 전투 규칙, 저장 슬롯과 네 엔딩은 기존 계약을 유지한다. 이전 저장을 강제로 초기화하지 않는다.

## 자산 범위

외부 3D 모델 파일이 원본 자료에 없어 코드로 구성한 자체 스타일라이즈드 메시를 사용했다. 이는 실제 3D 모델이지만 전문 아티스트가 제작한 최종 캐릭터 모델이나 모션 캡처 애니메이션은 아니다. UI 글자와 소지품 아이콘은 일반적인 2D 인터페이스로 유지한다.

## 검증 명령

Play 모드에서 `Tools/Invoke-Campaign.ps1 -Action 3d`로 원근 카메라, 렌더 해상도, 14개 맵 메시·콜라이더, 42개 캐릭터 배치, 화면 방향, 초상화 픽셀 유효성을 확인한다. `tests`, `journey`, `branches`, `traversal`은 기존 규칙·진행 회귀 검증이다. 최신 실행 결과는 `Tools/3d-verification.txt`, `Tools/build-report.json`, `Builds/Windows/Verification/runtime-report.json`에 기록한다.

실행 결과: 3D 전용 검사 통과(구역당 최소 261개 MeshRenderer, SpriteRenderer 0개), 규칙 65개·진행 16개·분기 15개 통과. 14개 맵의 94개 조사 대상 접근 경로 통과. 실제 오른쪽 키 입력으로 위치가 (13.00, 9.00)에서 (13.77, 9.00)으로 이동한 것도 확인했다.

최종 Windows 빌드는 성공했고 오류 0개, 경고 1개였다. 경고는 에디터 코드 갱신과 플레이어 빌드 사이의 컴파일 시점에 관한 것이다. 앞선 시도에서 검증 보고서 필드의 에디터/플레이어 레이아웃 불일치가 발생해 보고서 형식을 유지하도록 수정했다. 최종 실행 파일의 실제 창에서 스모크 검사 PASS, 종료 코드 0, 런타임 오류 없음, 3D 머티리얼 지원 및 메시 월드 검사를 확인했다. 타이틀·공방·전투 스크린샷에서 입체 모델, 원근, 그림자, 3D 초상화 표시를 직접 확인했다.
